## 3. 到 96 的升级包

第一性原理：测量问题不是一组字段 bug，根因是**同一个事实在 report、board、cockpit 三处各算一遍**。修法是建立单一来源：所有效率指标只从 ledger 派生一次，三端共同消费；数据缺失时统一给出 `unknown`，不得填 0。这样才能从根本上消除 M1–M5 这类漂移，而不是一处处打补丁。

U1、U2、U3 的文件范围不重叠，同批并行派出；U4 依赖 U1。

## 4. 96 分以上仍值得做的升级（按效率收益排序）

1. **报表默认只输出摘要，明细按需读取**：目前 `superagent report` 默认输出约 11 MB。主控每次读取都在消耗上下文，这是最直接的 token 节省。
2. **独立 job 的用量计入需求账本**：290 个 run 里有 259 个没有需求归属。用 session/attempt 身份接入已有回执后，卡片派工也能进入完整的效率账本。
3. **自举回归**：引擎在派生会话里跑自己的测试套件，并把结果回填 ledger，持续守护“测试不受运行环境影响”。T0 和 T1 两次泄漏都是因为缺这一层。
4. **效率不变量做成机器校验**：`efficiency-constitution.md` 里有两处 `test.todo` 尚未实现。补齐后，在每个 run 结束时校验“合法等待闭集”和“故障即改派”。
5. **用 explore_ratio 驱动 tiers 的 effort**：U1 修好之后，按节点类型设定 p90 预算，自动给出 effort 调整建议，让测量结果真正落到配置上，而不只停留在报表里。
